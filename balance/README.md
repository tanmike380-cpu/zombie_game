# 战斗数值唯一入口

只修改 `balance/unit_balance.json`。它不在 `_Tests` 中；正式读取代码在
`Assets/_Game/Scripts/Balance/UnitBalance.cs`。

- 神机营：生命 100，移速 3.5 格/秒，伤害 20，间隔 0.8 秒，射程 7，弹速 40。
- 狂暴僵尸（当前红色）：生命 60，移速 4.5，伤害 10，间隔 1 秒，近战距离 1。
- 爆裂尸：生命 60，移速 4.25，爆炸伤害 70，半径 2，接触距离 1.2，引信 0.65 秒。
- 人类视野 10，僵尸视野 4；人类武器噪音 = 射程 × 2；僵尸爆炸永不发出吸引声音。
- `move_speed` 已经是最终速度，没有隐藏的测试场景速度倍数。
- `acceleration` 决定启动加速；`chase_repath_seconds` 控制移动目标追击刷新。
- `formation_spacing` 控制点击目标周围的紧凑站位间距，不保留分散部队之间的空白。

编辑后重新 Play 即生效，不承诺战斗中热更新。编辑器直接读原文件；每次构建自动
校验并生成 Resources 快照，独立程序读取同一份内容。快照被 Git 忽略，不手改。
启动日志 `[Balance]` 带内容 hash 和三类移速，可比较场景/构建是否使用相同配置。
缺失或不合法配置会报错，不回退到另一套写死的默认数值。

当前接入：小战斗、大地图战斗、旧群体移动、NavMesh 压测、十格声音测试。
NavMesh/群体移动测试使用狂暴僵尸移速；十格声音测试仍是慢速 walker，声音半径
引用弓箭手规则。不同测试兵种不同，但数值不再各自写死。

尚未实现的兵种保留已确定的速度/射程草案；`implemented: false`（省略也为 false）
的生命、伤害等缺失值是“尚未定”，不是可用的零伤害单位。实现新兵种前须填齐、
设为 true 并验证。`initial_balance.yaml` 只保留定位、资源和设计规则，不重复维护
这里已有的攻击/移动数值。原先的慢速 walker/胖尸等草案未擅自全部改成快尸。

测试参数（人数、地图尺寸、随机种子、采样时长、AI 调度预算）与兵种平衡分开。
改动数值或队形后，旧压测帧率/通关时间不能直接当成新版实测。
